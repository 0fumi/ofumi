# Androidアプリ設計

## 目的

御文を、毎朝30分で読める技術雑誌として届ける。

アプリの役割は、

> 「今日読むべき一冊を、迷わず開けること」
> 

である。

---

# 設計方針

## 🚀 v1

アプリは「情報を探す場所」ではない。

編集部が選んだ今日の御文を読む場所。

そのため、

- メニューを増やさない
- 検索を作らない
- 設定を作らない
- 情報量を増やさない

読書体験を優先する。

---

# 画面構成

## 画面一覧

```
📱 御文

├── ホーム
│
└── 記事詳細
```

v1では2画面構成。

---

# 1. ホーム画面

## 役割

「今日の御文」を開いた瞬間に、読む気持ちを作る。

雑誌でいう表紙。

---

## 構成

```
----------------

御文
2026.08.01

AIは書くから働くへ

AI活用は、
ツール導入から
仕事の再設計へ。

----------------

今日読む3本

① AIレビュー運用
② ...
③ ...

----------------

今日の一歩

次のPRでAIに
レビュー観点を聞く

----------------
```

---

## 表示要素

### 今日の日付

発行日を表示。

---

### 今日のひとこと

最重要。

ホームを開いた瞬間の「表紙」。

---

### 今日のサマリ

3行程度。

読む前の前提を作る。

---

### 今日読むべき3本

記事カード表示。

表示：

- タイトル
- バッジ
- 一言コメント

タップで詳細へ。

---

### 今日の一歩

最後に行動を提示。

---

# 2. 記事詳細画面

## 役割

ニュースを読む場所ではなく、

**仕事へ持ち帰る場所。**

---

## 構成

```
----------------

タイトル

🆕 新着
AIレビュー運用

編集部コメント

↓

要約

↓

なぜ重要？

↓

QAならこう使う

↓

今日の一歩

↓

原文を読む

----------------
```

---

## 表示要素

ホームの記事カードをタップすると開く。

表示：

- タイトル
- バッジ
- テーマ
- 編集部コメント
- 要約
- なぜ重要？
- QAへの応用
- 今日の一歩
- 原文リンク

# Android技術構成

## 採用

Kotlin + Jetpack Compose

---

## UI

Jetpack Compose

理由：

- 宣言的UI
- 少ないコードで画面を作れる
- 雑誌のような表現と相性が良い

---

## 状態管理

候補：

ViewModel

役割：

- JSONデータ保持
- 画面状態管理

---

## データ取得

v1：

```
Android

↓

GitHub Pages

↓

御文.json
```

# パッケージ構成

## 方針

画面単位ではなく、役割単位で分ける。

---

```
com.ofumi

├── app
│
├── data
│   ├── model
│   ├── repository
│   └── datasource
│
├── domain
│
├── ui
│   ├── home
│   ├── detail
│   └── component
│
└── util
```

---

# パッケージ役割

## data

データ取得担当。

例：

- JSON読み込み
- データモデル

---

## domain

御文のルール。

例：

- 今日の記事取得
- 表示用データ変換

---

## ui

画面表示。

### home

ホーム画面。

### detail

詳細画面。

### component

共通部品。

例：

- 記事カード
- バッジ
- セクションタイトル
