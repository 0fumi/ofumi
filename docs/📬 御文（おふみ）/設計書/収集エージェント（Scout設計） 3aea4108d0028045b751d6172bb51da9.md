# 収集エージェント（Scout設計）

## 目的

Scoutは、御文編集部の情報収集担当である。

世界中の技術情報から、Editorが判断するための記事候補を収集する。

Scoutの目的は、記事を選ぶことではない。

> **編集者が良い判断をするための素材を集めること**
> 

である。

---

# 設計方針

## 🚀 v1

無料で継続できる仕組みを優先する。

そのため、

- 有料APIを使わない
- 大規模なクローリングをしない
- 自動判断をしない
- 収集対象を絞る

---

# Scoutの役割

## やること

✅ 情報を集める

✅ 情報源を記録する

✅ 新しい記事を整理する

✅ Editorへ候補を渡す

---

## やらないこと

❌ 掲載判断

❌ 重要度評価

❌ 編集コメント作成

❌ 記事の価値判断

判断はEditorが行う。

---

# 実行タイミング

## 毎朝9:00

理由：

御文は朝読む技術雑誌である。

編集部は毎朝、新しい号を準備する。

---

# 出力形式

Scoutは記事候補一覧を生成する。

例：

```
{
  "collected_at":"2026-08-01T09:00:00",
  "articles": [
    {
      "title":"AI Testing Framework Released",
      "source":"GitHub Blog",
      "url":"https://example.com",
      "published_at":"2026-08-01",
      "category": ["AI","QA"
      ]
    }
  ]
}
```

---

# Editorへの引き渡し

Scoutの成果物：

## 記事候補一覧

含める情報：

- タイトル
- URL
- 情報源
- 公開日時
- カテゴリ
- 取得日時

---

含めない情報：

- おすすめ度
- 掲載理由
- 要約
- 編集コメント
