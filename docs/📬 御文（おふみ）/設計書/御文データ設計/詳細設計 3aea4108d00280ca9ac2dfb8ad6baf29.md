# 詳細設計

## 目的

御文データ詳細設計では、編集部が制作した「今日の御文」をAndroidアプリで表示するためのデータ構造を定義する。

御文v1ではデータベースを使用せず、JSONファイルを唯一のデータソースとする。

---

# 設計方針

## 🚀 v1

シンプルな発行形式を採用する。

優先すること：

- 編集しやすい
- Androidで読みやすい
- Git管理しやすい
- 将来拡張できる

---

# データ管理方式

## 採用

JSONファイル方式。

```
GitHub Repository

├── data
│   └── issues
│       └── 2026-08-01.json
│
└── app
```

---

# データ単位

御文は「1日1冊」として扱う。

```
1 JSON = 1冊の御文
```

---

# 全体構造

```
{
  "issue": {},
  "articles": [],
  "metadata": {}
}
```

---

# 1. issue（表紙情報）

御文そのものの情報。

---

## date

### 内容

発行日。

### 型

String

### 例

```
"date":"2026-08-01"
```

---

## title

### 内容

御文タイトル。

### 型

String

### 例

```
"title":"今日の御文"
```

---

## headline

### 内容

今日のひとこと。

ホーム画面の主役。

### 型

String

### 制約

1〜2文程度。

---

## summary

### 内容

今日のサマリ。

### 型

Array<String>

### 制約

3行程度。

例：

```
"summary": ["AI活用が開発現場へ広がっています","レビュー工程の変化が始まっています","今日は仕事への取り入れ方を考えます"
]
```

---

# 2. articles（記事情報）

今日読む記事一覧。

🚀 v1では3件。

---

## Article構造

```
{
  "id":"",
  "title":"",
  "source":"",
  "url":"",
  "badge":"",
  "theme":"",
  "editor_comment":"",
  "summary":"",
  "why_important":"",
  "work_application":"",
  "today_action":""
}
```

---

# Article項目

## id

### 内容

記事識別子。

### 目的

将来の履歴管理用。

例：

```
"article_001"
```

---

## title

### 内容

記事タイトル。

表示：

- ホーム
- 詳細

---

## source

### 内容

情報源。

例：

```
"Android Developers Blog"
```

---

## url

### 内容

原文URL。

---

## badge

### 内容

記事の位置づけ。

候補：

- NEW
- UPDATE
- TREND

---

## theme

### 内容

記事が属するテーマ。

例：

```
"AIレビュー"
```

---

## editor_comment

### 内容

編集部コメント。

目的：

「なぜ掲載したか」を伝える。

---

## summary

### 内容

記事要約。

目的：

何が起きたか理解する。

---

## why_important

### 内容

重要性。

目的：

なぜ今読む価値があるか理解する。

---

## work_application

### 内容

仕事への応用。

例：

- QAなら
- Androidなら

---

## today_action

### 内容

今日の一歩。

5〜10分で試せる行動。

---

# 3. metadata

管理情報。

---

## version

データ形式バージョン。

例：

```
"version":"1.0"
```

---

## created_at

作成日時。

---

## updated_at

更新日時。

---

```
{

    "created_at":"2026-08-01T09:00:00"
  }
}
```

# 🚀 v1では持たないもの

## Futureへ移動

### ユーザー情報

- user_id
- 閲覧履歴
- 保存状態

---

### 添え書き

理由：

ユーザーごとのデータになるため。

---

### 評価情報

- いいね
- 人気
- ランキング

理由：

御文は競争型メディアではない。
