# 技術選定

## 目的

御文を実現するための技術構成を定義する。

御文v1では、個人開発・無料運用を最優先とする。

そのため、データベースやサーバーを持たず、無料サービスの範囲内で成立する構成を採用する。

技術選定の基準は以下とする。

- 月額0円で運用できる
- 個人開発で管理できる
- 御文の読書体験を優先する
- 将来的な拡張を妨げない

---

# 技術方針

## 🚀 v1の考え方

御文v1では、完全自動AI編集部は作らない。

編集部の役割は以下で実現する。

- 🛰️ Scout：自動収集
- 📝 Editor：ofumi + AIで編集
- ✅ Reviewer：ofumiが確認
- 📱 Android：読者へ届ける

---

# システム構成

```
                  世界の情報源
                       │
                       ▼
                 🛰️ Scout
            GitHub Actions + Python
                       │
                       ▼
              記事候補データ
                       │
                       ▼
          📝 Editor（AI補助 + 手動編集）
                       │
                       ▼
              御文データ(JSON)
                       │
                       ▼
              GitHub Pages
                       │
                       ▼
              📱 Androidアプリ
```

---

# Androidアプリ

## 採用

**Kotlin + Jetpack Compose**

## 理由

- Android公式のモダン開発環境
- UIを柔軟に設計できる
- 個人開発との相性が良い
- 将来的な拡張が可能

## 役割

- 今日の御文を表示する
- 記事詳細を表示する
- 原文リンクを開く

---

# データ形式

## 採用

**JSONファイル**

## 理由

御文v1ではデータ量が少なく、データベースは不要。

「今日の一冊」を読むだけの体験では、ファイル配信で十分成立する。

---

## 保存するデータ

🚀 v1

- 日付
- 今日のひとこと
- 今日のサマリ
- 掲載記事
- 編集部コメント
- 記事要約
- 今日の一歩
- 原文URL

---

## 保存しないデータ

🚀 v1

- ユーザー情報
- 閲覧履歴
- 添え書き
- お気に入り
- 個人設定

理由：

御文v1は「毎日読む雑誌体験」に集中するため。

---

# 配信基盤

## 採用

**GitHub Pages**

## 理由

- 無料で利用可能
- JSONファイルの配信に十分
- サーバー管理が不要

## 役割

Androidアプリへ最新の御文データを提供する。

---

# 情報収集基盤

## 採用

**GitHub Actions**

## 役割

毎日9:00にScoutを実行する。

## 処理

```
毎日9:00

GitHub Actions起動

↓

情報源取得

↓

記事候補整理

↓

Editor向けデータ生成
```

---

# Scout実装

## 採用候補

**Python**

## 理由

- RSS/API取得が容易
- 情報処理との相性が良い
- AI関連ライブラリが豊富

## 役割

- 技術記事収集
- 記事情報整理
- JSON生成補助

---

# AI利用方針

## 🚀 v1

アプリ内AIは利用しない。

AIは編集部の補助として利用する。

## 利用

- Codex
- ChatGPT

## 用途

- 記事要約
- 編集部コメント作成
- QA視点への変換
- 今日の一歩作成
