# UIデザインコンセプト

## デザインテーマ

# 「朝、机の上に届く技術雑誌」

御文を開いた瞬間に感じてほしいこと。

> 「今日はこれを読めばいいんだ」
> 

ニュースアプリのような忙しさではなく、

静かに集中できる読書体験を目指す。

---

# デザイン原則

## 1. 情報ではなく、余白を届ける

技術情報は詰め込みたくなる。

しかし御文は、

「読む量を減らすこと」

に価値がある。

そのため、

- 大きな余白
- 少ない要素
- ゆったりした行間

を重視する。

---

## 2. 雑誌の表紙のように

ホーム画面はアプリのトップではなく、

「今日号の表紙」

として設計する。

イメージ：

```
────────────────

御文

2026.08.01

AIは書くから働くへ

今日の技術業界は、
AI導入から仕事設計へ。

────────────────
```

---

## 3. 落ち着いた技術感

避けるもの：

- 派手なグラデーション
- 大量のカード
- 通知バッジだらけ
- SNSっぽいUI

目指すもの：

- 技術誌
- 研究ノート
- 編集部の机

---

# 🎨 カラーデザイン

## ベース

### 背景

白〜少し暖色寄り。

理由：

紙の雑誌感。

---

## メインカラー

候補：

### 墨色

落ち着き。

### 紺

技術・信頼感。

### 深緑

知性・研究感。

---

個人的には御文という名前なら、

**墨色 + 紙色**

がかなり似合うと思う。

「御文」って、少し和紙や文書のニュアンスがあるから。

---

# ✍️ フォント

## 重要度：高

雑誌感は文字で決まる。

---

## 見出し

特徴：

- 大きい
- 少し余韻がある
- 一文を読ませる

例：

```
AIは書くから働くへ
```

---

## 本文

特徴：

- 読みやすい
- 長文でも疲れない

---

# 📖 記事カード

普通のカードUIではなく、

「雑誌の目次」

として扱う。

例：

```

🌍 潮流

AI導入ではなく、
レビュー工程の変化を見る
```

少なめ。

# 避けるもの

🚫 未読バッジ

ユーザーが毎朝、

アプリを開いて、

> 「今日は何が起きたんだろう」
> 

ではなく、

> 「今日はこれを読めばいいんだ」
> 

と思う。
