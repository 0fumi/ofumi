# 御文データ設計

## 目的

御文データ設計では、編集部が制作した「今日の御文」をどのような構造で管理するかを定義する。

御文 v1ではデータベースを使用せず、JSONファイルを唯一のデータソースとする。

JSONフォーマットの詳細は **34_issue_json仕様** に定義する。

---

# 設計方針

## 🚀 v1

御文は「毎日発行される一冊」として扱う。

そのため、1日分の誌面を1つのJSONファイルとして管理する。

優先することは以下である。

* 編集しやすい
* Androidで読み込みやすい
* Gitで管理しやすい
* 将来拡張しやすい

---

# データ構造

御文は以下の3つで構成される。

```
今日の御文

├── 表紙
│
├── 記事（最大3本）
│
└── 今日の一歩
```

## 表紙

その日のテーマを読者へ伝える。

主にホーム画面で表示される。

含まれる情報の例

* 発行日
* 今日のひとこと
* 今日のサマリ

---

## 記事

その日読むべき記事をまとめる。

v1では最大3本掲載する。

各記事は

* 原文情報
* 編集部コメント
* 要約
* なぜ重要か
* 仕事への応用

を持つ。

詳細な項目は **34_issue_json仕様** を参照する。

---

## 今日の一歩

御文全体を読み終えたあと、

読者が今日すぐ試せる行動を1つ提示する。

記事単位ではなく、御文全体で1つだけ持つ。

---

# データ保存

v1ではGitHub上でJSONファイルとして管理する。

```
content/

└── issues/
    ├── latest.json
    ├── 2026-08-01.json
    ├── 2026-08-02.json
    └── ...
```

通常、Androidアプリは `latest.json` を取得する。

過去号を表示する場合は日付ごとのJSONを利用する。

# JSON仕様

この設計書ではデータの考え方のみを扱う。
